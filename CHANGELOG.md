# Changelog

All notable changes to this project will be documented in this file.

## Unreleased

### Added

- **Command leash for the reference policies** (`unienv_genesis_refpolicy.base.motion.leash_command`), opt-in on `GoToRefPolicy` (and subclasses) and `BoxGripperGraspPolicy`: `max_command_lead` (m) / `max_command_lead_angle` (rad) clamp every command — the interpolated pose, a carried `continue_command` hand-off, or the (pre-)grasp / GoTo target itself when it is commanded without interpolation — onto the ball / cone of that radius around the *achieved* EEF pose (position clipped along the lead, rotation slerped from the achieved one), and a clamped command restarts its speed ramp from rest. The lead is measured on the arm controller's own EEF (the flange under a tip-frame view), so a rotation about the tool tip counts toward it. Without it the interpolated command runs ahead of an arm that cannot follow (joint-rate limits, contact): on `droid_sim_real`'s FR3 the command led the flange by 3–6 cm median and up to ~40 cm. `None` (default) keeps the previous behaviour.
- **Ramped motion and command hand-off for the interpolating reference policies** (`unienv_genesis_refpolicy.base.motion`), opt-in on `GoToRefPolicy` (and subclasses) and `BoxGripperGraspPolicy`: `ramp_seconds` gives the straight-line motion a trapezoidal speed profile (accelerate to the cruise speeds within `ramp_seconds`, decelerate to stop at the target) instead of jumping from rest to full speed; `continue_command=True` starts a phase from the commanded pose, speed and direction the previous interpolating phase on the same arm left behind (stored on the arm controller, shared by tip-frame views), when that command is within 5 cm / 0.5 rad of the EEF, so consecutive phases join without stopping at the achieved pose.
- **Task props** (`unienv_genesis_collection.objects.props`): the dustpan, hand brush, three crumpled paper balls and small shelf modelled in Blender (`scripts/blender/make_props.py`, moved from `droid_sim_real`), hosted with the collection assets under `objects/props/<name>/` and loaded on first use. Each is a `UrdfPropObject`: a single-link URDF whose geometry (bounding box, grasp candidates) is the union of its designed convex collision pieces, with `visual_trimesh()` / `surface_mesh()` for the rendered surface. `dustpan(fixed=False)` is a free body by default (a hand can pick it up); `fixed=True` welds it to the world.
- **Tighter set-down for `PickPlaceRefPolicy`**: `lower_kwargs` override the transport kwargs for the `lower` phase only (e.g. a smaller `position_threshold` / `orientation_threshold`: a transport phase ends as soon as the EEF is within its tolerances, while the arm may still be moving, and the release then holds that pose — with the 2 cm / ~50° transport tolerances `droid_sim_real`'s pickplace let objects go ~4 cm off the goal), and `place_clearance` (m) lowers the object to that height above the goal instead of pressing it into the table. Defaults keep the previous behaviour.

### Changed

- **`GoToRefPolicy` interpolates by default**: `max_linear_speed` / `max_angular_speed` default to `DEFAULT_MAX_LINEAR_SPEED` (0.15 m/s) / `DEFAULT_MAX_ANGULAR_SPEED` (0.4 rad/s) instead of `None`, so the commanded pose moves along the straight line from the EEF to the target (also for `GoToLambdaRefPolicy`, `MoveObjectPolicy`, `MoveObjectLambdaPolicy` and `PickPlaceRefPolicy`'s motion phases). Pass `max_linear_speed=None, max_angular_speed=None` for the previous behaviour (the target commanded at once). `BoxGripperGraspPolicy` still interpolates only with explicit speeds.
- **ZED cameras render from 1 cm** (`unienv_genesis_collection.sensors.cameras.zed`): the ZED Mini / ZED 2i (2.1 mm, 4 mm) option helpers used each sensor's minimum depth range as the near clipping plane (0.1 / 0.3 / 1.5 m), which cut close-by objects out of the RGB image too — a head-mounted exterior camera lost the robot's own forearm, a wrist camera the gripper fingers. They now clip at `ZED_NEAR_CLIP` (0.01 m; `near=0` gives NaN depth in Genesis's rasterizer and NYX rejects it); the minimum depth ranges are `ZED_MINI_MIN_DEPTH` / `ZED_2I_WIDELEN_MIN_DEPTH` / `ZED_2I_NARROWLEN_MIN_DEPTH` for masking depth like the sensors. Pass `near=` to keep the old clipping.

### Fixed

- **`PickPlaceRefPolicy` proposes grasps for the current target object after a scene reload**: a zero-argument `candidate_provider` factory in `grasp_kwargs` was resolved on the first grasp node only and the shared kwargs overwritten with that provider, so after a reload that swapped the target object the grasp phase kept proposing grasps from the *first* object's geometry (mesh, bounding box, box-likeness) at the new object's pose, and most grasps missed (`droid_sim_real` pickplace collection, same reloaded scene: 3/16 episodes kept, 13 grasp failures, vs 10/10 with the fix). The factory is now called for every grasp node the graph builds (each full reset).
- **Scene rebuilds no longer accumulate GPU memory**: `GenesisWorld.reload` destroyed the previous scene but left its objects to Python's cyclic garbage collector, and the GPU memory they hold (solver fields, renderer buffers) stayed allocated until a full collection happened to run: about 0.6 GB per rebuild of an 8-env scene with two 720p cameras, enough to run a long collection with periodic rebuilds out of GPU memory. `reload` now runs `gc.collect()` after destroying the old scene (about 0.2 GB per rebuild remains).
- **Forward kinematics works on Genesis 1.4.4**: Genesis removed `RigidEntity.forward_kinematics` (genesis-world#3233) in favour of `KinematicSolver.forward_kinematics_query(entity, qpos)`, which takes the full configuration and returns every link. The controllers' `compute_eef_pose_from_qpos` and the `get_action_dict` built on it, and the robot node's `forward_kinematics`, raised `AttributeError`. They now go through `unienv_genesis.utils.forward_kinematics`, which keeps the old call shape (a subset of coordinates, the others at their current values; a subset of links) on either Genesis API.
- **Joint-limit-bounded controller spaces carry the batch dimension**: Genesis 1.4 reports `get_dofs_limit` / `get_dofs_force_range` once, `(n_dofs,)`, in a batched world too, so the controllers' `joint_position` / `joint_motor_torque` observation spaces and their joint-position action spaces (e.g. a hand's `target_joint_position`) were `(n_dofs,)` against `(batch_size, n_dofs)` observations and actions. The limits are broadcast to the batch where the controllers read them.
- **`CameraSensorNode` observations now match their declared space in shape and dtype**, whatever the renderer. Genesis's non-batched renderers (`Rasterizer`, `RayTracer`) render one environment and return it without a batch dimension, also in a batched world of one, so a `batch_size=1` world rendered by the Rasterizer (the single-env setup of e.g. `droid_sim_real`'s collection scene) reported `depth` / `seg` / `normal` / `position` as `(H, W[, C])` and `extrinsics_cv` / `local_extrinsics_cv` as `(3, 4)` against `(1, ...)` spaces; the first masked `WorldEnv.reset` then failed slicing them by the mask. The leaves are now conformed to the space at the end of `update_observation` (a batch dimension of one added in a batched world, dropped in an unbatched one) and cast to the declared dtype: the Rasterizer's `int64` segmentation is reported as the declared `int32`, as the `BatchRenderer` already did. A static NYX camera without depth / segmentation (no secondary genesis camera) reports its shared pose and intrinsics once; in a batched world they are now expanded to every environment (they were `(3, 4)` / `(3, 3)` against `(B, ...)` spaces). A non-batched renderer *rendering images* for a batched world of several environments raises a `RuntimeError` naming the `BatchRenderer` instead of reporting one environment's image (or failing later in the position map).
- **The hand brush's bristles render in Nyx**: Nyx reads a URDF itself and draws only the first `<visual>` of a link ([genesis-nyx#23](https://github.com/Genesis-Embodied-AI/genesis-nyx/issues/23)), so the brush's separate bristle mesh was missing from every Nyx image (the brush seemed to float 3 cm above its support). The brush's wood and bristles are now one multi-material visual OBJ (`hand_brush_body.obj`); its collision pieces are unchanged.

## 0.0.2a2 (2026-10-17)

### Added

- **Gripper tip frame for the reference policies** — gripper controllers take the optional `eef_tip_offset` (`(3,)` position in the arm EEF frame) and `eef_tip_offset_quat` (`(w, x, y, z)`) attributes (`EntityController.extra_attributes`), and `unienv_genesis_refpolicy.base.tip_frame.tip_frame_controller(arm, gripper)` returns a `TipFrameEEFController` view of the arm controller whose EEF poses, IK targets and world-frame action targets are tip poses (the IK error and the actions stay the arm controller's). `BoxGripperGraspPolicy`, `PickPlaceRefPolicy` and `MoveObjectPolicy` (with a `gripper_controller`) wrap the arm controller themselves, so the arm controller's EEF can be the robot flange while grasps still place the fingertips. Without `eef_tip_offset` the tip is the EEF and nothing changes.
- **Space metadata on every space** (unienv ≥ 0.0.1b16): the observation and action spaces of the controllers, sensors and tasks describe their data with the unienv vocabulary, so wrappers, storages and dataset exporters find e.g. the camera images by `kind` without knowing the node (`validate_metadata` passes on all of them). Cameras: `rgb` is an `image` (`rgb` / `HWC`), `depth` metres (`HW`, with `near` / `far`), `seg` a `segmentation` map with the scene's segmentation `level`, `normal`, `position` a world `pointcloud`, and the `*_cv` matrices OpenCV `intrinsics` / `extrinsics` with their `reference_frame`; `source` is the node name (plus `entity` / `link` when attached); `fps` is omitted, since a camera renders once per environment step. Joint readings and targets carry per-DOF `units` (`rad` / `rad/s` / `N*m` for revolute DOFs, `m` / `m/s` / `N` for prismatic and free-joint linear DOFs) and `names` from the entity's joints; root / EEF poses their `frame` (`world`, or `base` with a configured base frame) and `quat_wxyz`. Actions state `control` / `mode`: joint position / velocity targets, the EEF pose with the `rotation` of its `rotation_representation` (`euler` → `euler_rxyz`, the intrinsic XYZ convention it decodes; `quat` → `quat_wxyz`; `rot6d`), and a mimic controller configured as a gripper is a normalized `gripper` command with `open_value` / `closed_value`. IMU, contact force / flag and keypoint-tracker leaves carry units and frames; task goals are `kind="task"`, and `OpenArticulatedJointTask`'s `joint_position` is labelled as the normalized open fraction it is, not a joint coordinate. Shared helpers: `unienv_genesis.utils.space_metadata` (`dof_units`, `dof_names`, ...).
- **`FocusedSegmentationPointProposer`** (keypoint tracker): `n_focus_points` of the points on the *focus* entities (`focus_entity_names`, a list or a callable resolved at every proposal — e.g. the objects a task moves), the rest over the other tracked entities, either group filling the other's budget when it shows too few pixels; within a group the points are spread over the candidates' 3D positions by farthest-point sampling from a random start (`sampling="fps"`, `farthest_point_sample`) or drawn at random. Candidates exclude silhouette pixels (`edge_margin`, `interior_mask`): their rendered depth can belong to the background, and farthest-point sampling picked exactly those outliers (a point 20 m behind a hammer). The `UniformSegmentationPointProposer` with `randomize=False` takes each entity's first pixels in raster order, which put all of an object's points on its top silhouette rows (1–3 image rows, 2–3 cm of a 13 cm object).
- **Render-free rollouts and re-rendering recorded states** (`CameraSensorNode`): `render_on_step=False` (constructor argument or attribute) skips the per-step render, so a camera renders only on reload / reset and keeps its last frame; rendering does not affect the physics (measured bit-identical rollouts with and without it, Nyx and rasterizer), so such a rollout can be rendered afterwards. `invalidate_render_cache()` makes the next `update_observation()` render the current scene state after a state set without stepping (e.g. `rigid_solver.set_qpos`), which the per-step render caches would otherwise hide; with it, call `scene.visualizer.update_visual_states(force_render=True)` once, since Genesis refreshes the visual states (and the Nyx camera attachments) only when the step advances.
- **Cartesian interpolation** for `GoToRefPolicy` (and its subclasses `MoveObjectLambdaPolicy` / `GoToLambdaRefPolicy`) and for `BoxGripperGraspPolicy`'s PRE_GRASP / APPROACH phases — opt-in `max_linear_speed` (m/s) / `max_angular_speed` (rad/s). Without them the target pose is commanded at once and the EEF follows the arm's joint-space path, which arcs: a sweep stroke lifted the brush off the desk and hopped over the debris, and an 8 cm grasp descent near the robot base drifted 2 cm sideways and landed a finger on a hammer handle. With either speed set, the commanded pose starts at the EEF pose on `reset()` and advances along the straight line (slerp for the rotation, position and rotation synchronized) by at most those speeds per `step()`; reach / stall checks still compare the actual EEF pose with the final target. The step is `goto_policy.step_pose_toward`. Defaults (`None`) keep the previous behaviour.
- **Realistic GSO masses** — `mass=` on `MeshObject` / `HubAssetMeshObject` / `GSOObject` (kg), plus a resolved default for every GSO object. The dataset ships no masses, so Genesis derived each object's mass from its geometry at MuJoCo's default 1000 kg/m³: a plush bib came out at 3.8 kg and a LEGO advent calendar at 13.5 kg, 10–100× the real product weight, which put a grasped object at or beyond the Robotiq 2F-85's friction limit. `GSOObject.resolve_mass()` now resolves the explicit `mass=`, else the curated `GSO_MASSES` table (real product weights for the objects the clutter pools draw on most: toys/boxed sets, soft goods, cups/bowls, tools, ink cartridges …), else `GSO_MASS_DENSITY` (200 kg/m³, a plausible hollow-household-object density) applied to the collision-hull volume and clamped to `GSO_MASS_BOUNDS`. Genesis only accepts `entity.set_mass()` on a *built* scene, so the override runs through the new `ManipulatableObject.apply_mass(entity)` hook (no-op by default, overridden by `MeshObject`/`GSOObject`), which `ClutteredTableManager.after_reload` and `ObjectRelocateTask.after_reload` call after the build and before the first placement/physics step. Verified on the 4090: `entity.get_mass()` equals the intended value for explicit, curated and density-fallback objects, and the FR3 + Robotiq gripper (fingers closed on the object, arm raised) carries the objects it used to drop — LEGO calendar 13.5 → 0.4 kg, Melissa & Doug See & Spell 7.5 → 0.7 kg, plush bib 3.8 → 0.08 kg.
- **Gravity-compensation feedforward** for the joint-position controllers (`gravity_compensation=` on `JointPositionAndVelocityController` and subclasses, incl. `EndEffectorPoseController`): `GravityFeedforward` writes the gravity torque `g(q)` of the controlled joints into Genesis' actuator feedforward `act_bias[0]` every `apply_action`, removing the PD steady-state sag while the motors still carry the load. The value is a factor (`True` = `1.0` exact; `0.0`/`False` off; e.g. `0.9`/`1.1` to model a real robot that under-/over-compensates). Batched worlds need `RigidOptions(batch_dofs_info=True)`; velocity control rejects it.
- **Levelled top-down grasps** (`MeshObject.list_box_gripper_grasping_candidates_local(rest_clearance=0.007)`): each antipodal pair also gets a clean top-down variant — approach along the upright down, closing axis made horizontal, at the same contact midpoint, lifted so the fingertips are `rest_clearance` above the object's resting plane (its lowest point in the upright pose) — kept only if it still closes on surface. On a round or slanted handle lying on a table, the sampled closing axes are tilted, and a tilted axis swings the lower open finger (42.5 mm out) 1–4 cm below the grasp point, so no grasp cleared a 5 mm table clearance (spatula, flat screwdriver, hammer: 0 clean top-down grasps clearing it); levelled, they get 50 / 108 / 200. `rest_clearance=None` disables it.
- **Quality-weighted grasp sampling** — `BoxGripperGraspPolicy(selection_temperature=T)`: with a provider cost, the grasp is drawn per env with weight `exp(-(score - best) / T)` (`score` = IK error + cost) instead of always the best; filtered-out and unreachable candidates get zero weight. The policy's own generator (on the world device) is reseeded by `reset(seed=...)`, so a seed reproduces its draw while different episodes vary — e.g. for data collection, where a poor best grasp should not be repeated every episode. `None` (default) keeps the deterministic choice.
- **Grasp-candidate selection on the provider** — `GraspCandidateProvider` gains optional `filter(candidates)` / `cost(candidates)` hooks (default: keep all, no cost). `BoxGripperGraspPolicy` uses the provider's `filter` when it is not given a `filter_candidate_fn`, and ranks the *reachable* candidates (IK error within `ik_error_threshold`) by IK error + the provider's `cost`; an unreachable candidate never wins, and the IK gate still sees the IK error alone. `ObjectGeometryGraspCandidateProvider` implements both, opt-in for table-top scenes: `table_z` / `min_table_clearance` prefer grasps whose *lowest open-finger point* (`lowest_finger_z`) clears the table, `prefer_top_down` prefers approaches within 60° of down (each with a per-env fallback), and `quality_cost` ranks by approach tilt, contact depth below the object's top and distance from its centre. With `bbox_grasps=True` it also appends axis-aligned grasps across opposing bounding-box faces for *box-like* objects (mesh volume ≥ `bbox_min_fill_ratio`, 0.6, of the bbox), with downward ones moved to a finger-depth below the top face; on 20-seed pick tasks they still win grasps the antipodal sampler misses on a blister-packed ink cartridge. Without these options the stock provider behaves as before.

### Fixed

- **`get_action_dict_space` of `MimicJointPositionAndVelocityController`** described `target_joint_velocity` with the scalar control-signal space; it now describes the per-joint velocity targets `get_action_dict` returns.
- **Misspelled controller options were silently ignored**: `EntityController.__init__` stored every keyword argument no controller consumed as an attribute, so a typo (`max_joint_pos_vell=`) or an option meant for another controller (e.g. `metadata=` in a robot or sub-controller config) was accepted and had no effect. Leftover options now raise an `UnknownControllerOptionWarning`; they are still stored, since configs rely on extra attributes — the gripper description the grasp policies read (`approach_direction`, `open_direction`, `gripper_width`, `gripper_depth`, `gripper_open_action`, `gripper_close_action`), which is now the documented `EntityController.extra_attributes` allowlist and stays silent.
- **Clutter piling up across episodes** (`ClutteredTableManager`): a reset of a single environment (every reset of a one-env world, and the per-env masked resets of batched collection) wrote its table placements into the cached parking positions — `expand(...).contiguous()` returned a view of the cache when the reset scope had one env — so an object once placed was "parked" back at its old table spot afterwards. The table filled up episode after episode (9 → 23 objects for `n_objects_range=(3, 8)`), with stale objects overlapping new placements; with 32-piece convex decompositions the broad phase overflowed (`Exceeding max number of broad phase candidate contact pairs (1200)`, peak 1566 candidate pairs on a sweep collection; 177 after the fix). The placement buffer is now a copy.
- **`CameraSensorNode.set_pose` with one env**: the Rasterizer camera (CPU or unbatched scenes) rejects `envs_idx`, so a single-env pose is now set without it.
- **GSO objects rendered untextured in Nyx** (`GSOObject.load_into_scene`): the Nyx exporter serializes an MJCF entity's visual mesh *from memory* into a shared per-scene export folder, and every textured mesh writes the same generic `material.mtl` / `material_0.png` pair there — so all GSO objects of a scene ended up sharing one (the last-written) texture, or none at all. The loader now binds the MJCF-referenced `texture.png` explicitly as `gs.surfaces.Plastic(diffuse_texture=gs.textures.ImageTexture(...))`, which the exporter emits as a per-instance albedo-texture override pointing at that object's own texture. Rasterizer renders are unchanged (verified byte-identical); the multi-object Nyx render went from flat white to the correct box art / handle colours.
- **Antipodal grasp candidates closed on air** (`MeshObject.list_box_gripper_grasping_candidates_local`): the sampler approached *along* the antipodal pair axis and closed the jaws along `cross(approach, z)` — perpendicular to the pair, across a width it never checked. Its pair test was also only "normals ≥ 120° apart", with no check that the axis between the points lies in either friction cone or that the normals face away from each other. Ray-cast against the real meshes, 0–25 % of its candidates (2–4 % on most objects, 0 % on `sugar_box`) put material between the jaws with in-cone contact normals. The sampler is rewritten: (1) pairs need opposed normals (`pair_normal_deg`, 20°), each within `pair_axis_deg` (30°) of the pair axis or offset sideways by at most `pair_lateral_tol` (3 mm — thin plates such as an ink box's 1 mm cardboard hang tab, which an angular cone alone never pairs; `min_grasp_width` drops 5 → 0.5 mm for the same reason), and the jaws close along the *averaged contact normal*, so they meet both faces square-on; pairs whose closing axis leaves no approach within the tilt cap are dropped before selection; (2) pairs are spread over the object — one per (1 cm midpoint voxel, ~30° closing-direction) bucket, up to `max_pairs` — instead of bunching where the surface area is; (3) approaches are tilted `approach_tilts_deg` about the closing axis from the object's *upright* down (`standing_quaternion`) and capped at `max_approach_tilt_deg` (60°), instead of spinning 360°; (4) against a dense surface sample with normals, a grasp whose palm (`gripper_depth` behind the fingertip EEF point) would enter the object slides back along the approach until it clears — tall boxes now get top-down grasps near the top — finger-slab collisions are rejected, and every kept grasp must close on surface whose outermost contacts face outward within `friction_cone_deg` (15°) and are `min_grasp_width`..`gripper_width` apart. Grasp widths leave `width_margin` (1 cm) of slack below the gripper opening, so the open jaws clear both faces despite pose error; the stock provider's bbox grasps use the same `width_margin`. The pair search is vectorised (`n_samples` 100 → 1000, ≤ 0.25 s per object).

## 0.0.2a1 (2026-10-08)

### Added

- **`RoomBuilder` scene offset** (`pos`/`yaw`, `TableBuilder` convention): the room frame (floor centre) can be placed at any world position and rotated about Z. The offset is captured at construction as read-only `pos`/`yaw` properties, identical across batched envs. Everything internal — the layout spec and baked JSON, procedural placement, `_occupied` overlap rejection, `set_furniture_pose_3d` — stays room-frame, and the world conversion happens exactly once at morph load: shell morphs (procedural primitives and baked shells, via `EntityGroup.world_pose`) and furniture morphs (`placement_world_pose`, composed as `room_quat ⊗ (yaw ⊗ standing_quaternion)`), so no post-build `set_pose` is needed and `batch_fixed_verts` batched worlds stay correct. Defaults (`(0, 0, 0)` / `0.0`) preserve the previous behaviour.
- **Amazon Berkeley Objects (ABO)** rigid object family: all 7,953 modelled Amazon.com products (CC BY 4.0 — Amazon.com relicensed ABO from CC BY-NC 4.0 in mid-2023) as `ABOObject` / `get_abo_catalog` / `list_abo_objects` / `make_abo_pool` under `objects/abo/<3dmodel_id>/`, with `scripts/prepare_abo_assets.py` as the packager (downloads the models CSV + listings shards, joins `3dmodel_id`, bakes the Y-up → Z-up rotation into `model.obj` so the trimesh bounding box and the placed frame agree, renames the OBJ texture to `texture.png` and rewrites the `.mtl`/`.obj` references, generates the broad → detailed language annotations from `item_name`/`bullet_point`, writes the provenance `README.md` + verbatim CC BY 4.0 `LICENSE` and prints the `hf upload` line). Collision comes from Genesis's own `convexify` at load time (the dataset ships no decomposition); `box_gripper_graspable` is baked into `scripts/data/abo_graspable.json` — computed inline from the converted meshes and merged by every run, so an incremental `--objects`/`--limit` run extends the bake and the full run completes it (`scripts/compute_graspable.py abo` re-bakes it from a prepared tree).

### Changed

- Relaxed the `genesis-world` pin to `>=1.4` (verified 1.4.3 in-tree: no ABD/numerics change — the pinned regression probe was byte-identical source, bit-identical results). Genesis 1.4.3 no longer installs the compute device as torch's *ambient* default from `gs.init()` (upstream #3431), so tensors built without an explicit `device` now land on CPU on a GPU run. Device audit of the collection: `base_object`/`room_builder`/both clutter managers/tasks/`EntityGroup` already pin or inherit devices correctly and were left alone; the one genuine hazard fixed is `TableBuilder`, whose `size`/`height`/anchor-pose tensors inherited the ambient default and feed `PickPlaceTask.sample_target_placement` (CUDA `xy` · CPU `placement_half_xy` device-mismatch on a GPU world) — they are now pinned to `world.device` like every other world-frame quantity. One follow-on hardening from the same change: the offline FK walker installs genesis's own `gs.EPS` fallback (`gs.init(precision="32")`'s exact value) before calling `gu.polar`, whose numba kernel reads `gs.EPS` as a compile-time global — `EPS` is `None` until `gs.init`, and whether that crashes (`float64 > none` `TypingError`) or not used to depend on numba's *disk cache* being warm from a previous genesis install (a reinstall invalidates it, which is how the 1.4.3 upgrade surfaced this). Both compat patches verified still required and still applying under 1.4.3; the full scoped suite, the robot/controller suites and the batched/CUDA suites (725 tests) pass under 1.4.3, and a CUDA sanity-gate smoke (`refrigerator_fridge` through `_gate_worker.py` with `genesis_compat.install()`) loads + gates + renders on the 4090 with offline-FK vs `vAABB` Δ ≤ 6e-8 m.

### Added

- Three new USD asset families in the articulated rooms pack, following the ArtVIP integration: **MolmoSpaces** (Ai2-THOR subset, CC BY 4.0 — the packaged stages carry the mandatory joint-body0/body1 swap), **Lightwheel SimReady** open bundle (CC BY-NC 4.0, maintainer-accepted — packaged stages carry the OmniPBR MDL → UsdPreviewSurface material rewrite) and **NVIDIA SimReady Warehouse** rigid props (CC BY 4.0, `RigidBodyAPI` authored at packaging, metersPerUnit normalised to 1.0).
